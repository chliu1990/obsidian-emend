## Architecture contract

- Emend is desktop-only and requires Obsidian 1.11.4 or newer. DeepSeek `deepseek-flash` at `https://api.deepseek.com`, Kimi `k3.1-pro` at `https://api.kimi.com/coding/v1`, and custom HTTP(S) endpoints use one OpenAI-compatible streaming `fetch` transport with Server-Sent Events. Preset URLs and models remain editable.
- Ask, Discuss, and Brainstorm have no note writer. For DeepSeek `deepseek-flash` and `deepseek-v4-pro`, their composer Web control supports default-off Off/Review/Auto retrieval. The model directs sequential Search/Fetch calls with required extraction goals across multiple rounds within a default eight-call executed-call setting (1–20). An over-limit batch executes only the remaining calls in model order, skips the excess with `call_limit_reached` outcomes/activities, and forces one terminal main-model answer without Web tools; chat persists a singular/plural skipped-call incompleteness warning only when calls were skipped. Every readable executed result invokes one same-provider extraction and verification loop: a bounded AI extractor produces compact question-focused claims backed by exact verbatim quotes, a verifier marks support, and up to two no-tools refine rounds replace rejected claims. The main answering model receives only actual source metadata plus verified claims with their quotes, or quotes-only evidence when no claim for that source survived verification, never raw retrieval or unverified AI-generated facts. Each complete serialized extraction payload has an independent character cap, defaulting to 20,000 and normalized to 1,000–100,000, so `N` executed calls contribute at most `C × N` characters. Only actual HTTP(S) sources represented by successful extractions become stable citations. Kimi/custom providers and unsupported models fail clearly without silent unsearched fallback. See [Stage 36](devel_docs/36-deepseek-online-search.md).
- Main Web model rounds use ordinary captured context/history/instructions, while Search/Fetch endpoints receive only validated visible arguments. Review permits editing every executable query/URL and extraction goal; Auto skips only that pause. Continuations preserve all proposed call IDs, reviewed executable arguments, original skipped arguments, and selected/skipped outcomes. The forced terminal request uses current note/chat and successful evidence without tools, permits no-evidence answers without invented citations, and rejects further tool calls without retrieval. The same-provider extractor receives the current typed question, goal, target, and source catalog, but no note context, history, instructions/skills, additional notes, or vault access. It inspects temporary canonical retrieval through bounded local grep/read tools for at most 6 model rounds, 4 local calls per round, 16 local calls total, and 4,000 characters per local result, then receives one forced no-tools JSON request at the round limit. Output is parsed tolerantly from fenced or prose-wrapped JSON with unknown fields and invalid individual claims/quotes dropped; unknown and duplicate source IDs are ignored or merged. Claims carry trimmed 1–500-code-point text and 1–4 exact verbatim quotes of 1–1,500 code points each; deduplicated result-level quotes are the fallback. Claims are capped at 8 per source and 24 total before verification, and every verifier request, including after refinement, is capped at 24,000 serialized claim characters; claims outside that budget fall back to result-level quotes. One same-provider correction round handles structurally unparseable terminal output, and a second unparseable reply is a `format` failure. A verifier receiving only the question, goal, and numbered claims with quotes (never the target or note/chat context) marks support across at most 3 passes; claims, quotes, and verifier reasons are framed as untrusted external data, rejected claims get up to 2 no-tools refine rounds, and verifier failure falls back to quotes without failing the extraction. After the reader returns its verified outcome, the coordinator's single payload fit always respects the per-call cap by dropping trailing claims, then trailing evidence, then prefix-truncating the last quote with `truncated`, then dropping empty results or emitting `no_relevant_evidence`; it never passes raw content through. Verified claim results retain their extractor quotes so fitting can degrade them to quotes when claims are dropped. Reader, correction, verifier, and refine rounds, including failed requests recorded with an empty synthetic result, may incur separate charges and are included in all-round provider-versus-estimated usage; their reasoning and artifacts remain transient. Expected Fetch failures return explicit unread outcomes and a visible incompleteness warning. Only non-abort extractor provider/format/limit failures exclude that query's sources and add one aggregate extraction warning. Search and Fetch each make one immediate retry only for a failure without an HTTP status, `429`, `500`–`599`, or an empty Fetch page; `403`/`404` are not retried, while Search/Fetch HTTP 400/401/402/413 and aborts remain fatal. An exhausted Search becomes a non-fatal `search_failed` outcome that lets the model continue on other evidence, and failed activities carry transient `network`/`http`/`empty`/`reader` reasons shown as activity labels but never persisted. Ready answers append warnings in the order unread pages, extraction failures, failed searches (`Emend could not complete N web search. The answer may be incomplete.`; `searches` when N > 1), cap-fitting omissions (`Emend omitted some extracted evidence to fit the per-call output cap. The answer may be incomplete.`), then skipped calls. Cap measurement uses UTF-16 characters behind a token-ready interface, not an exact tokenizer. Retrieved text is untrusted and never gains a writer. See [Stage 40](devel_docs/40-web-content-budget-diagnostics.md).
- Edit and Modify Selection apply validated CriticMarkup immediately after completion, abort, exact-source, active-target, and permission checks. Track Changes is the only review surface; web research is not available to either editing path or to Edit quick actions.
- Operations are the only model-facing edit protocol. The closed JSON command union validates exact original-snapshot ranges atomically and compiles into the internal CriticMarkup path; there is no edit-strategy setting. Typed actionable diagnostics preserve conservative overlap/insertion rules, while deterministic Unicode word/segment-level replacement minimization uses response-scoped work bounds and whole-target fallback for backtick-containing replacements and a single-substitution fallback for expensive replacements. After one replacement-compilation pass, structural guards use actual `compiledText` to reject partial inline-code targets (`inline-code-range`), fenced-code edits (`fenced-code-edit`), and table structure edits (`table-structure-edit`) before final CriticMarkup validation and either writer. Tables permit only text within one existing header/body cell, with escaped pipes and safe cell Operations preserved. Candidate-validation failure permits exactly one same-provider correction with bounded feedback and at most two total calls; provider, stale, and write failures remain terminal. Full-note usage covers all rounds, and transient candidates/feedback never enter ready chats or stored threads. See [Stage 37](devel_docs/37-minimal-edit-ranges.md) and [Stage 38](devel_docs/38-markdown-edit-safeguards.md).
- Full-note Edit sends the complete captured note. The composer **Edit target** control automatically displays **Selection** for usable selected text and **Full note** otherwise, resets automatic choice on actual target-note changes, and preserves an explicit choice across same-note renders and mode switches. Typed Edit and all quick actions follow the maintained displayed target; Selection capture failures produce no request, message, save, write, or full-note fallback. Composer Selection and the unchanged Command Palette modal send the complete selection with empty provider history plus default smart structural context or the symmetric opt-out; context expansion never expands the replacement target. Both selection entry points use native `editor.replaceRange` undo and share replacement minimization/correction, while explicit Full note retains the guarded vault writer. Composer Selection stores concise chat results with all-round usage and successful-attempt reasoning; the modal retains its existing notices without chat, usage, or retry-status displays. See [Stage 39](devel_docs/39-easier-selection-editing.md).
- Additional notes are explicitly picked Markdown files with per-target, session-only selections shared by chat and Modify Selection. Their fresh bounded snapshots are read-only in every mode, use a separate combined source-character budget with fair allocation and omission markers, and never become edit targets. Active-note deduplication, rename/delete handling, missing-path failure, and reload clearing are covered in [Stage 35](devel_docs/35-additional-notes-context.md).
- Vault-root `AGENTS.md` and directly referenced skills are loaded for every request, with skills placed before agent instructions. Note paths are shared only when explicitly enabled.
- Ready per-note conversations and token-usage metadata persist locally through versioned atomic storage. Conversation schema 2 loads version 1 and adds ready Web badges, sanitized citations, and folded query/URL/outcome activity. Raw retrieval arguments/results, request bodies, note snapshots, transient activity/messages, and full edit responses are not persisted. Provider credentials persist separately in Obsidian SecretStorage, while plugin `data.json` keeps every `apiKey` empty.
- Web usage is provider-reported only when every model round has a complete valid triplet; otherwise every round is estimated independently and labeled as estimated. No search pricing or token counts are invented.
- The Track Changes plugin is required to review accepted annotations. Emend intentionally has no in-plugin Apply/Reject or diff UI.

## Verification and release process

Run the clean local gate from the repository root:

```bash
npm ci
npm test
npm run lint
npm run build
git diff --check
```

Real-Obsidian verification uses only the ignored `test_vault/`, Track Changes, local OpenAI-compatible chat/search/fetch mocks with CORS, and dummy credentials. It must not use real provider accounts, paid calls, or other vaults. Stage 39 records the current composer Selection matrix, actual request/note-byte/persistence evidence, and its Linux/CDP limits; no real-provider smoke is claimed.

GitHub Actions runs lint, tests, and the production build through `.github/workflows/ci.yaml` on `ubuntu-latest` with Node 24. For a later release, `npm version <patch|minor|major>` synchronizes `package.json`, `package-lock.json`, `manifest.json`, and `versions.json`. Create or dispatch a tag that exactly matches the manifest version, without a leading `v`; `.github/workflows/release.yaml` verifies it and publishes `main.js`, `manifest.json`, and `styles.css` as individual GitHub release assets after all checks pass.
