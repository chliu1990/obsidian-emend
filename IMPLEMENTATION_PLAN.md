## Architecture contract

- Emend is desktop-only and requires Obsidian 1.11.4 or newer. DeepSeek `deepseek-flash` at `https://api.deepseek.com`, Kimi `k3.1-pro` at `https://api.kimi.com/coding/v1`, and custom HTTP(S) endpoints use one OpenAI-compatible streaming `fetch` transport with Server-Sent Events. Preset URLs and models remain editable.
- Ask, Discuss, and Brainstorm have no note writer. For DeepSeek `deepseek-flash` and `deepseek-v4-pro`, their composer Web control supports default-off Off/Review/Auto retrieval. The model directs sequential Search/Fetch calls with required extraction goals across multiple rounds within a default eight-call executed-call setting (1–20). An over-limit batch executes only the remaining calls in model order, skips the excess with `call_limit_reached` outcomes/activities, and forces one terminal main-model answer without Web tools; chat persists a singular/plural skipped-call incompleteness warning only when calls were skipped. Every readable executed result invokes one same-provider extraction and verification loop: a bounded AI extractor produces compact question-focused claims backed by exact verbatim quotes, a verifier marks support, and up to two no-tools refine rounds replace rejected claims. The main answering model receives only actual source metadata plus verified claims with their quotes, or quotes-only evidence when no claim for that source survived verification, never raw retrieval or unverified AI-generated facts. Each complete serialized extraction payload has an independent character cap, defaulting to 20,000 and normalized to 1,000–100,000, so `N` executed calls contribute at most `C × N` characters. Only actual HTTP(S) sources represented by successful extractions become stable citations. Kimi/custom providers and unsupported models fail clearly without silent unsearched fallback. See [Stage 36](devel_docs/36-deepseek-online-search.md).
- Main Web model rounds use ordinary captured context/history/instructions, while Search/Fetch endpoints receive only validated visible arguments. Review permits editing every executable query/URL and extraction goal; Auto skips only that pause. Continuations preserve all proposed call IDs, reviewed executable arguments, original skipped arguments, and selected/skipped outcomes. The forced terminal request uses current note/chat and successful evidence without tools, permits no-evidence answers without invented citations, and rejects further tool calls without retrieval. The same-provider extractor receives the current typed question, goal, target, and source catalog, but no note context, history, instructions/skills, additional notes, or vault access. It inspects temporary canonical retrieval through bounded local grep/read tools for at most 6 model rounds, 8 local calls per round, 24 local calls total, and 4,000 characters per local result; calls beyond the remaining per-round or total allowance return `local_call_limit_reached` without discarding inspected evidence, a per-round overflow alone continues so the model can retry, and total-cap overflow or a sixth round with calls receives one forced no-tools JSON request. Output is parsed tolerantly from fenced or prose-wrapped JSON with unknown fields and invalid individual claims/quotes dropped; unknown and duplicate source IDs are ignored or merged. Claims carry trimmed 1–500-code-point text and 1–4 exact verbatim quotes of 1–1,500 code points each; deduplicated result-level quotes are the fallback. Claims are capped at 8 per source and 24 total before verification, and every verifier request, including after refinement, is capped at 24,000 serialized claim characters; claims outside that budget fall back to result-level quotes. One same-provider correction round handles structurally unparseable terminal output, and a second unparseable reply is a `format` failure. A verifier receiving only the question, goal, and numbered claims with quotes (never the target or note/chat context) marks support across at most 3 passes; claims, quotes, and verifier reasons are framed as untrusted external data, rejected claims get up to 2 no-tools refine rounds, and verifier failure falls back to quotes without failing the extraction. After the reader returns its verified outcome, the coordinator's single payload fit always respects the per-call cap by dropping trailing claims, then trailing evidence, then prefix-truncating the last quote with `truncated`, then dropping empty results or emitting `no_relevant_evidence`; it never passes raw content through. Verified claim results retain their extractor quotes so fitting can degrade them to quotes when claims are dropped. Reader, correction, verifier, and refine rounds, including failed requests recorded with an empty synthetic result, may incur separate charges and are included in all-round provider-versus-estimated usage; their reasoning and artifacts remain transient. Expected Fetch failures return explicit unread outcomes and a visible incompleteness warning. Only non-abort extractor provider/format/limit failures exclude that query's sources and add one aggregate extraction warning. Search and Fetch each make one immediate retry only for a failure without an HTTP status, `429`, `500`–`599`, or an empty Fetch page; `403`/`404` are not retried, while Search/Fetch HTTP 400/401/402/413 and aborts remain fatal. An exhausted Search becomes a non-fatal `search_failed` outcome that lets the model continue on other evidence, and failed activities carry transient `network`/`http`/`empty`/`reader` reasons, reader failure kinds, and non-fatal HTTP statuses shown as activity labels but never persisted. Ready answers append warnings in the order unread pages, extraction failures, failed searches (`Emend could not complete N web search. The answer may be incomplete.`; `searches` when N > 1), cap-fitting omissions (`Emend omitted some extracted evidence to fit the per-call output cap. The answer may be incomplete.`), then skipped calls. Cap measurement uses UTF-16 characters behind a token-ready interface, not an exact tokenizer. Retrieved text is untrusted and never gains a writer. See [Stage 40](devel_docs/40-web-content-budget-diagnostics.md).
- Edit responses accept a bare operations array or a `{summary, operations}` envelope. The optional model-written summary is trimmed, capped at 2,000 UTF-16 code units with word-boundary, code-point-safe truncation plus `…`, attached only after structural and Stage 07 validation, shown in chat, never written into the note, and never persisted as a structured field. An applied result shows the unchanged `Edit applied — N changes tracked. Review in Track Changes.` header, a `Target: Full note.` or `Target: Selection.` line, the optional summary, and at most eight sanitized Markdown bullets describing applied Operations by note-absolute line (`Inserted text before/after line N.`, `Removed`/`Replaced`/`Commented on` line or `lines N–M.`); Selection adds `snapshot.from` exactly once, `changeCount` is the applied preparation's tracked-hunk count, and bullets include no anchors, targets, text, comments, or JSON. No-ops keep exactly `No changes were needed.` or that line plus a blank line and the summary, with no target line or bullets. Correction returns only the successful candidate's summary and bullets. Failures and pre-write aborts show no ready or persisted summary, and the Command Palette modal remains notice-only. Composer full-note and Selection requests use the configurable `historyMessageLimit` ready-message window (default 8, 0–50, `0` disables); the modal sends none. Track Changes is the only review surface; web research is not available to either editing path or to Edit quick actions. See [Stage 41](devel_docs/41-post-edit-change-summaries.md).
- Each provider has optional, nullable **Context window (tokens)** and **Output reserve (tokens)** settings plus a persisted invalid marker; effective input capacity is `window − reserve`, and the reserve is local accounting only, never sent as `max_tokens`. No limits are inferred or fetched, and nothing is applied automatically, but an explicit **Use documented defaults** button covers only DeepSeek `deepseek-flash`/`deepseek-v4-pro` at `1048576`/`393216` (1M context, 384K maximum output) and Kimi `k3.1-pro` at `1048576`/`131072` (up to 1M context on eligible plans and 131,072 default output; lower-tier plans may need a smaller window). These documentation values are not account-specific provider responses; custom/unknown models remain manual, and no provider metadata call is added. A shared module sums UTF-16 characters for the system prompt, user prompt, formatted history, tool continuations (including tool-call names and arguments), and tool declarations, and estimates `max(1, ceil(chars / 4))` per nonempty category; this is a predictive approximation, not a tokenizer or billing data. Every read-only, full-note, and Selection submission is preflighted after fresh additional-note/instruction reads and an abort check, and every provider fetch — later Web main rounds, extractor/verifier/refine rounds, and the single correction round — re-checks the same rule. Aborts win over capacity, and an invalid or exceeded capacity is terminal: no retry, no correction, no Web/reader degradation, no partial answer, and no write. The chat header below its mode controls and the selection modal below the title show a compact accessible capacity bar, with no composer meter. Known system/draft/history/tools/optional-continuation segments, free input `max(0, W − R − I)`, and right-hand remaining output `max(0, min(R, W − I))` use proportional widths bounded to the layout; unconfigured/invalid states have no fabricated partition and there is no gray unknown segment. Hover/focus opens floating per-category details with the unmeasured-content/lower-bound note; category text matches its segment colors, and the meter uses `aria-labelledby` with its summary rather than a native-tooltip-producing `aria-label`. Click pins the details, and outside click or document Escape dismisses them. The estimate excludes loaded instructions/skills, additional-note contents, the first Web round's system prompt and tool declarations, and later Web/correction rounds, and blocks Send, the affected quick actions, and keyboard submission at or above capacity or with invalid settings. No compact-context button, compression, threshold, tokenizer, additional-note estimation, or invented model limit is included. See [Stage 42](devel_docs/42-context-accounting-capacity.md).
- Operations are the only model-facing edit protocol. The closed JSON command union validates exact original-snapshot ranges atomically and compiles into the internal CriticMarkup path; there is no edit-strategy setting. Typed actionable diagnostics preserve conservative overlap/insertion rules, while deterministic Unicode word/segment-level replacement minimization uses response-scoped work bounds and whole-target fallback for backtick-containing replacements and a single-substitution fallback for expensive replacements. After one replacement-compilation pass, structural guards use actual `compiledText` to reject partial inline-code targets (`inline-code-range`), fenced-code edits (`fenced-code-edit`), and table structure edits (`table-structure-edit`) before final CriticMarkup validation and either writer. Tables permit only text within one existing header/body cell, with escaped pipes and safe cell Operations preserved. Candidate-validation failure permits exactly one same-provider correction with bounded feedback and at most two total calls; provider, stale, and write failures remain terminal. Full-note usage covers all rounds, and transient candidates/feedback never enter ready chats or stored threads. See [Stage 37](devel_docs/37-minimal-edit-ranges.md) and [Stage 38](devel_docs/38-markdown-edit-safeguards.md).
- Full-note Edit sends the complete captured note. The composer **Edit target** control automatically displays **Selection** for usable selected text and **Full note** otherwise, resets automatic choice on actual target-note changes, and preserves an explicit choice across same-note renders, session switches, and mode switches. Typed Edit and all quick actions follow the maintained displayed target; Selection capture failures produce no request, message, save, write, or full-note fallback. Composer Selection sends the complete selection with the originating session's configured recent ready history plus default smart structural context or the symmetric opt-out; the unchanged Command Palette modal sends the same selection context with no history. Context expansion never expands the replacement target. Both selection entry points use native `editor.replaceRange` undo and share replacement minimization/correction, while explicit Full note retains the guarded vault writer. Composer Selection stores concise chat results with all-round usage and successful-attempt reasoning in the originating session; the modal retains its existing notices without chat, usage, or retry-status displays. See [Stage 39](devel_docs/39-easier-selection-editing.md) and [Stage 43](devel_docs/43-multiple-chat-sessions.md).
- Additional notes are explicitly picked Markdown files with per-target, session-only selections shared by chat and Modify Selection. Their fresh bounded snapshots are read-only in every mode, use a separate combined source-character budget with fair allocation and omission markers, and never become edit targets. Active-note deduplication, rename/delete handling, missing-path failure, and reload clearing are covered in [Stage 35](devel_docs/35-additional-notes-context.md).
- Vault-root `AGENTS.md` and directly referenced skills are loaded for every request, with skills placed before agent instructions. Note paths are shared only when explicitly enabled.
- Ready per-note conversations persist locally as schema-3 ordered session aggregates with exact IDs, manual order, last-active restore, automatic/manual titles, and token-usage metadata. Schema 1/2 threads load losslessly and migrate lazily on the first valid mutation; malformed files retain exact bytes until backed up on valid replacement, and future versions reject every mutation. New/Switch/Rename/Delete/Move controls make no provider calls. Drafts and provider history are isolated by `{notePath, sessionId}`, note/session/generation guards block stale completion/cleanup, and the existing pending lock remains per note across sessions and Modify Selection. Ready Web badges, sanitized citations/activity, main reasoning, and applied Edit results persist only in their originating session; raw retrieval arguments/results, request bodies, note snapshots, unknown artifacts, transient activity/messages, drafts, and full edit responses do not. Provider credentials persist separately in Obsidian SecretStorage, while plugin `data.json` keeps every `apiKey` empty; non-secret settings include the validated `historyMessageLimit` (default 8, 0–50, `0` disables). See [Stage 43](devel_docs/43-multiple-chat-sessions.md).
- Web usage is provider-reported only when every model round has a complete valid triplet; otherwise every round is estimated independently and labeled as estimated. No search pricing or token counts are invented.
- The Track Changes plugin is required to review accepted annotations. Emend intentionally has no in-plugin Apply/Reject or diff UI.

## Verification and release process

Run the clean local gate from the repository root:

```bash
npm ci
npm test
npm run lint
npm run build
git diff --check
```

Real-Obsidian verification uses only the ignored `test_vault/`, Track Changes, local OpenAI-compatible chat/search/fetch mocks with CORS, and dummy credentials. It must not use real provider accounts, paid calls, or other vaults. Stage 39 records the current composer Selection matrix, actual request/note-byte/persistence evidence, and its Linux/CDP limits; Stage 41 records the summary/target/no-op matrix, Selection-history regression, persistence evidence, its **40-file/1181-test** local gate, **17/17 scenario / 348-assertion** real-Obsidian loopback, and Linux/CDP limits; Stage 42 records the compact capacity bar/blocking/preflight/Web-and-correction-growth and explicit documented-defaults matrix, its **43-file/1388-test** PR-review gate, **27/27 scenario / 547-assertion** real-Obsidian loopback on the UI-polish tree at `4d37ce4` with bundle `a0da30c6…`, and its Linux/CDP limits. Stage 43 records the multiple-session controls/migration/race/cross-feature matrix, its **46-file/1523-test** gate and separate sanitizer RED→GREEN fix, **9/9 scenarios and 156/156 assertions** on `1780799` with bundle `896ed391ce6dd223a735625e28d383022599ff14606d807add85174d1dbfeaf4`, and Linux/CDP limits. No real-provider smoke is claimed.

GitHub Actions runs lint, tests, and the production build through `.github/workflows/ci.yaml` on `ubuntu-latest` with Node 24. For a later release, `npm version <patch|minor|major>` synchronizes `package.json`, `package-lock.json`, `manifest.json`, and `versions.json`. Create or dispatch a tag that exactly matches the manifest version, without a leading `v`; `.github/workflows/release.yaml` verifies it and publishes `main.js`, `manifest.json`, and `styles.css` as individual GitHub release assets after all checks pass.
