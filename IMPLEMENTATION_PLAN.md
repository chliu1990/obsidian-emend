This file indexes the implemented Emend rewrite and later numbered feature records. It is not a description of unfinished pseudocode or a second runtime specification.

Current behavior is documented in [README.md](README.md) and [AGENTS.md](AGENTS.md). ## Architecture contract

- Emend is desktop-only and requires Obsidian 1.11.4 or newer. DeepSeek `deepseek-flash` at `https://api.deepseek.com`, Kimi `k3.1-pro` at `https://api.kimi.com/coding/v1`, and custom HTTP(S) endpoints use one OpenAI-compatible streaming `fetch` transport with Server-Sent Events. Preset URLs and models remain editable.
- Chat has no note writer. For DeepSeek `deepseek-flash` and `deepseek-v4-pro`, its **Writing and web search** menu supports default-off Web Off/Review/Auto retrieval. The model directs sequential Search/Fetch calls with required extraction goals across multiple rounds within a default eight-call executed-call setting (1–20). An over-limit batch executes only the remaining calls in model order, skips the excess with `call_limit_reached` outcomes/activities, and forces one terminal main-model answer without Web tools; chat persists a singular/plural skipped-call incompleteness warning only when calls were skipped. Every readable executed result invokes one same-provider extraction and verification loop: a bounded AI extractor produces compact question-focused claims backed by exact verbatim quotes, a verifier marks support, and up to two no-tools refine rounds replace rejected claims. The main answering model receives only actual source metadata plus verified claims with their quotes, or quotes-only evidence when no claim for that source survived verification, never raw retrieval or unverified AI-generated facts. Each complete serialized extraction payload has an independent character cap, defaulting to 20,000 and normalized to 1,000–100,000, so `N` executed calls contribute at most `C × N` characters. Only actual HTTP(S) sources represented by successful extractions become stable citations. Kimi/custom providers and unsupported models fail clearly without silent unsearched fallback. See [Stage 36](devel_docs/36-deepseek-online-search.md).
- Ready and stopped chat bodies are seeded synchronously with their plain answer text before the detached Markdown render replaces them, so a completed Web answer is never blank while final rendering settles, and a rejected render keeps the seeded text with exactly one content element. A Web Review/Auto submission starts its transient loading message with `Researching the web...`, including when the model ends up making zero retrieval calls or pauses for Review, and only a loading message with neither reasoning nor activity shows `Waiting for a response...`. Both strings are transient UI text; nothing new is sent, persisted, or written. See [Stage 48](devel_docs/48-web-response-transition.md).
- Under the user-approved Stage 52 provisional-content policy, Web Review/Auto answer content streams immediately as a transient draft under the exact muted label `Draft answer — research may continue`. Each round's content deltas are forwarded; a round that returns any tool calls clears the draft once before Review or any Search/Fetch executes, and the terminal no-tool round is promoted unchanged into the ready answer without re-emitting already streamed text (aggregated content without deltas is emitted once). The `webDraft` flag is stripped before the ready snapshot and on every terminal-failure path, so ready, stopped, and error bodies never show the label and no draft text, flag, label, or evidence enters copy, provider history, or the schema-3 store. Stop keeps the visible partial as `Stopped`; Web Off is unchanged and never shows the label. See [Stage 52](devel_docs/52-web-draft-streaming.md).
- Main Web model rounds use ordinary captured context/history/instructions, while Search/Fetch endpoints receive only validated visible arguments. Review permits editing every executable query/URL and extraction goal; Auto skips only that pause. Continuations preserve all proposed call IDs, reviewed executable arguments, original skipped arguments, and selected/skipped outcomes. The forced terminal request uses current note/chat and successful evidence without tools, permits no-evidence answers without invented citations, and rejects further tool calls without retrieval. The same-provider extractor receives the current typed question, goal, target, and source catalog, but no note context, history, instructions/skills, additional notes, or vault access. It inspects temporary canonical retrieval through bounded local grep/read tools for at most 6 model rounds, 8 local calls per round, 24 local calls total, and 4,000 characters per local result; calls beyond the remaining per-round or total allowance return `local_call_limit_reached` without discarding inspected evidence, a per-round overflow alone continues so the model can retry, and total-cap overflow or a sixth round with calls receives one forced no-tools JSON request. Output is parsed tolerantly from fenced or prose-wrapped JSON with unknown fields and invalid individual claims/quotes dropped; unknown and duplicate source IDs are ignored or merged. Claims carry trimmed 1–500-code-point text and 1–4 exact verbatim quotes of 1–1,500 code points each; deduplicated result-level quotes are the fallback. Claims are capped at 8 per source and 24 total before verification, and every verifier request, including after refinement, is capped at 24,000 serialized claim characters; claims outside that budget fall back to result-level quotes. One same-provider correction round handles structurally unparseable terminal output, and a second unparseable reply is a `format` failure. A verifier receiving only the question, goal, and numbered claims with quotes (never the target or note/chat context) marks support across at most 3 passes; claims, quotes, and verifier reasons are framed as untrusted external data, rejected claims get up to 2 no-tools refine rounds, and verifier failure falls back to quotes without failing the extraction. After the reader returns its verified outcome, the coordinator's single payload fit always respects the per-call cap by dropping trailing claims, then trailing evidence, then prefix-truncating the last quote with `truncated`, then dropping empty results or emitting `no_relevant_evidence`; it never passes raw content through. Verified claim results retain their extractor quotes so fitting can degrade them to quotes when claims are dropped. Reader, correction, verifier, and refine rounds, including failed requests recorded with an empty synthetic result, may incur separate charges and are included in all-round provider-versus-estimated usage; their reasoning and artifacts remain transient. Expected Fetch failures return explicit unread outcomes and a visible incompleteness warning. Only non-abort extractor provider/format/limit failures exclude that query's sources and add one aggregate extraction warning. Search and Fetch each make one immediate retry only for a failure without an HTTP status, `429`, `500`–`599`, or an empty Fetch page; `403`/`404` are not retried, while Search/Fetch HTTP 400/401/402/413 and aborts remain fatal. An exhausted Search becomes a non-fatal `search_failed` outcome that lets the model continue on other evidence, and failed activities carry transient `network`/`http`/`empty`/`reader` reasons, reader failure kinds, and non-fatal HTTP statuses shown as activity labels but never persisted. Ready answers append warnings in the order unread pages, extraction failures, failed searches (`Emend could not complete N web search. The answer may be incomplete.`; `searches` when N > 1), cap-fitting omissions (`Emend omitted some extracted evidence to fit the per-call output cap. The answer may be incomplete.`), then skipped calls. Cap measurement uses UTF-16 characters behind a token-ready interface, not an exact tokenizer. Retrieved text is untrusted and never gains a writer. See [Stage 40](devel_docs/40-web-content-budget-diagnostics.md).
- Edit responses accept a bare operations array or a `{summary, operations}` envelope. The optional model-written summary is trimmed, capped at 2,000 UTF-16 code units with word-boundary, code-point-safe truncation plus `…`, attached only after structural and Stage 07 validation, shown in chat, never written into the note, and never persisted as a structured field. An applied result shows the unchanged `Edit applied — N changes tracked. Review in Track Changes.` header, a `Target: Full note.` or `Target: Selection.` line, the optional summary, and at most eight sanitized Markdown bullets describing applied Operations by note-absolute line (`Inserted text before/after line N.`, `Removed`/`Replaced`/`Commented on` line or `lines N–M.`); Selection adds `snapshot.from` exactly once, `changeCount` is the applied preparation's tracked-hunk count, and bullets include no anchors, targets, text, comments, or JSON. No-ops keep exactly `No changes were needed.` or that line plus a blank line and the summary, with no target line or bullets. Correction returns only the successful candidate's summary and bullets. Failures and pre-write aborts show no ready or persisted summary, and the Command Palette modal remains notice-only. Composer full-note and Selection requests use the configurable `historyMessageLimit` ready-message window (default 8, 0–50, `0` disables); the modal sends none. Track Changes is the only review surface; web research is not available to either editing path or to Edit quick actions. See [Stage 41](devel_docs/41-post-edit-change-summaries.md).
- Each provider has optional, nullable **Context window (tokens)** and **Output reserve (tokens)** settings plus a persisted invalid marker; effective input capacity is `window − reserve`, and the reserve is local accounting only, never sent as `max_tokens`. No limits are inferred or fetched, and nothing is applied automatically, but an explicit **Use documented defaults** button covers only DeepSeek `deepseek-flash`/`deepseek-v4-pro` at `1048576`/`393216` (1M context, 384K maximum output) and Kimi `k3.1-pro` at `1048576`/`131072` (up to 1M context on eligible plans and 131,072 default output; lower-tier plans may need a smaller window). These documentation values are not account-specific provider responses; custom/unknown models remain manual, and no provider metadata call is added. A shared module sums UTF-16 characters for the system prompt, user prompt, formatted history, tool continuations (including tool-call names and arguments), and tool declarations, and estimates `max(1, ceil(chars / 4))` per nonempty category; this is a predictive approximation, not a tokenizer or billing data. Every read-only, full-note, and Selection submission is preflighted after fresh additional-note/instruction reads and an abort check, and every provider fetch — later Web main rounds, extractor/verifier/refine rounds, and the single correction round — re-checks the same rule. Aborts win over capacity, and an invalid or exceeded capacity is terminal: no retry, no correction, no Web/reader degradation, no partial answer, and no write. The compact chat header and the selection modal title have a compact accessible capacity bar directly below them, with no composer meter. Known system/draft/history/tools/optional-continuation segments, free input `max(0, W − R − I)`, and right-hand remaining output `max(0, min(R, W − I))` use proportional widths bounded to the layout; unconfigured/invalid states have no fabricated partition and there is no gray unknown segment. Hover/focus opens floating per-category details with the unmeasured-content/lower-bound note; category text matches its segment colors, and the meter uses `aria-labelledby` with its summary rather than a native-tooltip-producing `aria-label`. Click pins the details, and outside click or document Escape dismisses them. The estimate excludes loaded instructions/skills, additional-note contents, the first Web round's system prompt and tool declarations, and later Web/correction rounds, and blocks Send, the affected quick actions, and keyboard submission at or above capacity or with invalid settings. No compact-context button, compression, threshold, tokenizer, additional-note estimation, or invented model limit is included. See [Stage 42](devel_docs/42-context-accounting-capacity.md).
- Operations are the only model-facing edit protocol. The closed JSON command union validates exact original-snapshot ranges atomically and compiles into the internal CriticMarkup path; there is no edit-strategy setting. Typed actionable diagnostics preserve conservative overlap/insertion rules, while deterministic Unicode word/segment-level replacement minimization uses response-scoped work bounds and whole-target fallback for backtick-containing replacements and a single-substitution fallback for expensive replacements. After one replacement-compilation pass, structural guards use actual `compiledText` to reject partial inline-code targets (`inline-code-range`), fenced-code edits (`fenced-code-edit`), and table structure edits (`table-structure-edit`) before final CriticMarkup validation and either writer. Tables permit only text within one existing header/body cell, with escaped pipes and safe cell Operations preserved. Candidate-validation failure permits exactly one same-provider correction with bounded feedback and at most two total calls; provider, stale, and write failures remain terminal. Full-note usage covers all rounds, and transient candidates/feedback never enter ready chats or stored threads. See [Stage 37](devel_docs/37-minimal-edit-ranges.md) and [Stage 38](devel_docs/38-markdown-edit-safeguards.md).
- Full-note Edit sends the complete captured note. The composer **Writing and web search** menu offers Chat, **Chat · Selection**, **Edit · Selection**, **Edit · Selection · Full note**, and **Edit · Full note** plus Chat-only Web choices. Ordinary Chat retains bounded note context; Chat Selection captures exact current offsets and sends the complete note with a separate complete read-only focus section through the writer-free read-only coordinator, failing closed without a usable selection. Automatic Edit targeting resolves Selection for usable selected text and Full note otherwise, resets on actual target-note changes, and preserves an explicit choice across same-note renders, session switches, and mode switches. Chat Selection and full-note Selection context are per-view choices retained across same-note sessions and reset to ordinary Chat/Default on an actual target-note change. Typed Edit and all Edit-only quick actions follow the maintained displayed target and Selection-context policy; Selection capture failures produce no request, message, save, retrieval, write, or fallback. Composer Selection sends the complete selection with originating-session ready history and either unchanged Default Smart/Symmetric context or explicit complete-note supporting context. Modify Selection offers Default (Smart/Symmetric) and Full note with no history, resets to Default on every open, and disables its selector while pending. Full-note/focus prompts duplicate the selection intentionally and capacity uses the same prompt assembly; context never expands Operation anchors or the replacement target. Both selection entry points use native `editor.replaceRange` undo and share replacement minimization/correction, while explicit Full note retains the guarded vault writer. Composer Selection stores concise chat results with all-round usage and successful-attempt reasoning in the originating session; the modal retains its notices without chat, usage, or retry-status displays. See [Stage 39](devel_docs/39-easier-selection-editing.md), [Stage 43](devel_docs/43-multiple-chat-sessions.md), [Stage 44](devel_docs/44-compact-composer.md), and [Stage 49](devel_docs/49-selection-focus-and-context.md).
- The compact header contains only title, build identity, and active-note label. Capacity remains directly after it, followed by session controls and messages. One accessible Writing/Web trigger summarizes ordinary/focused Chat Off/Review/Auto or any of the three Edit targets; its eight-item menu disables Web in Edit without clearing the retained Chat choice, closes on rerender/view close, and uses the trigger's owner document in popouts. The adjacent native model button summarizes catalog provider, current model, and reasoning effort with a full tooltip/accessibility name. Its base rule uses `flex: 0 1 auto` and `max-width: min(100%, 320px)` with zero minimum width, automatic inline-start margin, and ellipsis; it does not grow to fill wide rows, while the under-400 px full-basis wrapping rule remains unchanged. Its owner-document menu has separate Model and active-provider Reasoning effort sections. Model groups include only providers with a nonempty SecretStorage key and a usable built-in/cached-discovered/trimmed-current option; Custom needs both key and model, unavailable groups are omitted, and no qualifying providers shows disabled No available models beside the separate reasoning section. Availability uses the existing secret-free `emend-api-key-<provider>` IDs and refreshes through real Settings saves without discovery. Model selection derives that provider's latest current effort inside its queued updater; reasoning selection uses its explicit effort and retains the latest current model, so both overlap orders preserve the other committed value. Blank active-provider current models disable effort items/callbacks while valid model items remain enabled. A choice performs one queued sanitized updater save against the latest settings, refreshes every open view and capacity estimate after applying values into the existing root/providers/provider-config objects, closes stale open menus, and makes no discovery, note read, provider request, or write. All no-argument, object-candidate, and updater saves share one rejection-tolerant plugin queue; composer updaters reapply at commit to preserve overlapping Settings edits, and open Settings/discovery closures retain live identities. Pending saves/requests/threads/session mutations disable dependent controls and refuse submissions; failed saves retain live settings and permit retry. Targeted updates preserve drafts/caret/focus, sessions/messages, Related notes, Writing/Web and Edit targets, while unsupported retained Web choices still fail without unsearched fallback. **Refresh models** and custom free-text model editing remain Settings-only. **Related notes** opens an owner-document explorer with explicit All/Links snapshots, full-path search, folder and Select-all helpers, manual Refresh, a count and expandable paths with Remove/Clear and submission disclosure, and no pre-submission content read or provider request. Decorative Obsidian folder/file icons precede names without replacing native controls. Initial expansion reveals only the active note's ancestor chain, with every folder collapsed for a root active note; manual choices survive mode switches and Refresh, new folders start collapsed, and search overrides visibility without changing expansion state. Collapsed-folder descendants have enforced hidden display, and the floating panel chooses below only when its preferred height fits or below has at least as much space as above, otherwise using the viewport-bounded space above. Fix grammar, Make concise, and Add examples appear only in Edit. Empty composer placeholders disclose Enter/Mod+Enter and Shift+Enter; icon Send/Stop controls retain accessible names. Default mode is limited to Chat/Edit, with legacy read-only default values normalized to Chat. Both native composer menus accept the current selected item after Obsidian's native hide-before-click ordering; opening another menu, refreshing model settings, pending state, and control destruction still reject stale callbacks. See [Stage 44](devel_docs/44-compact-composer.md), [Stage 45](devel_docs/45-related-notes-explorer.md), [Stage 46](devel_docs/46-composer-model-controls.md), and [Stage 50](devel_docs/50-native-menu-activation.md).
- Additional notes are explicitly picked Markdown files with per-target, session-only selections shared by chat and Modify Selection. Chat discovery uses vault paths and resolved-link/file-cache metadata without body scans; All excludes the active note, Links deduplicates outgoing/incoming resolved links, and incomplete caches produce a conservative disclosure. Opening captures one snapshot, search and mode switches reuse it, and only explicit Refresh recaptures paths/links and resolves all retained helpers against that same snapshot. Manual and helper provenance preserves overlapping membership on deselection, individually removed matching paths can return on Refresh, and removed helpers never return. Their fresh bounded snapshots are read-only in every mode, use a separate combined source-character budget with fair allocation and omission markers, and never become edit targets. Active-note deduplication, rename/delete handling, missing-path failure, and reload clearing are covered in [Stage 35](devel_docs/35-additional-notes-context.md) and [Stage 45](devel_docs/45-related-notes-explorer.md). Automatic linked/folder inclusion and automatic TOCs are not implemented.
- Vault-root `AGENTS.md` and directly referenced skills are loaded for every request, with skills placed before agent instructions. Note paths are shared only when explicitly enabled.
- Ready per-note conversations persist locally as schema-3 ordered session aggregates with exact IDs, manual order, last-active restore, automatic/manual titles, and token-usage metadata. Schema 1/2 threads load losslessly and migrate lazily on the first valid mutation; malformed files retain exact bytes until backed up on valid replacement, and future versions reject every mutation. New/Switch/Rename/Delete controls sit directly after the capacity bar and before messages and make no provider calls; reorder remains a deferred management-page operation with its pure/store helpers preserved. Drafts and provider history are isolated by `{notePath, sessionId}`, note/session/generation guards block stale completion/cleanup, and the existing pending lock remains per note across sessions and Modify Selection. Ready Web badges, sanitized citations/activity, main reasoning, and applied Edit results persist only in their originating session; raw retrieval arguments/results, request bodies, note snapshots, unknown artifacts, transient activity/messages, drafts, and full edit responses do not. Provider credentials persist separately in Obsidian SecretStorage, while plugin `data.json` keeps every `apiKey` empty; non-secret settings include the validated `historyMessageLimit` (default 8, 0–50, `0` disables). See [Stage 43](devel_docs/43-multiple-chat-sessions.md).
- Web usage is provider-reported only when every model round has a complete valid triplet; otherwise every round is estimated independently and labeled as estimated. No search pricing or token counts are invented.
- A focused `StateField<DecorationSet>` in `selection-presentation.ts` decorates every nonempty current selection with `emend-selection-highlight`. It initializes from `state.selection`, rebuilds from `transaction.state.selection` only when `transaction.docChanged || transaction.selection !== undefined`, retains the prior set for unrelated transactions, and provides decorations through `EditorView.decorations.from(field)`. Every nonempty range is normalized with minimum/maximum endpoints before `Decoration.mark().range()`, preserving reversed selections and tolerating inverted ranges produced by whole-document CodeMirror selection remapping; collapsed ranges still return `Decoration.none`. One `registerEditorExtension(createSelectionPresentation())` call lets Obsidian dispose the extension on unload. The sole CSS declaration is `background: var(--text-selection)`. This live-state presentation survives chat/non-chat blur and whole-document restoration without stale stored offsets, selection/document mutation, focus changes, persistence, provider requests, content reads, or note writes; whitespace presentation does not change Edit targeting. See [Stage 47](devel_docs/47-selection-highlight.md) and [Stage 49](devel_docs/49-selection-focus-and-context.md).
- The Track Changes plugin is required to review accepted annotations. Emend intentionally has no in-plugin Apply/Reject or diff UI.
