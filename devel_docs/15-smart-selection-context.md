# Stage 15: Expand smart selection context without expanding the edit target

## Goal

Add deterministic paragraph-aware context for Modify Selection while preserving the exact captured selection offsets and text. Enable smart context by default with an opt-out that restores Stage 09's symmetric before/after window. Handle YAML frontmatter, fenced code, omissions, and over-budget blocks deliberately without changing provider, validation, write, stale-target, or abort behavior.

## Plan

1. Write test-first fixtures for partial sentences, multiline and spanning paragraphs, blank-line boundaries, document edges, adjacent-block budgets, oversized selections, YAML frontmatter, fenced code, settings normalization, the opt-out prompt, and exact replacement offsets.
2. Add a focused `buildSmartSelectionContext(fullText, from, to, maxCharacters)` module returning the unchanged target and complete selection alongside context text. Expand containing blocks first and adjacent blocks only when their complete source text fits.
3. Treat document-leading YAML and complete fenced blocks as structural units. When a containing unit exceeds the budget, retain the complete selection and use symmetric in-block truncation with exact `[...]` omission markers.
4. Add a default-on **Smart selection context** setting. Disable it to use the unchanged Stage 09 symmetric context builder and before/after prompt fields. Keep CriticMarkup validation and native `editor.replaceRange` targets tied only to the original snapshot.
5. Run focused red/green tests, the full local gate, and real isolated Obsidian verification with a loopback SSE mock. Record actual long-paragraph, toggle-off, YAML, and code requests plus exact resulting Markdown. Update usage/privacy documentation, self-review, commit and push, verify the dedicated Gitea runner, then record CI evidence separately.

## Implementation details

- `src/selection-context.ts` exports `SelectionContext { from, to, selectedText, contextText }` and `buildSmartSelectionContext()`. The returned offsets and selected text always come directly from the captured input; no expanded context offset is ever passed to validation or replacement.
- Structural blocks are blank-line-delimited paragraphs, complete document-leading YAML frontmatter, and complete backtick or tilde fenced code blocks, including internal blank lines. Unclosed YAML/fences extend to the end of the note rather than being split accidentally.
- The complete containing block or blocks are selected first. Whole adjacent blocks are then considered before-side first, then after-side, repeating while the source range fits the remaining budget. An adjacent block that does not fit is not partially included, and a side cannot skip over it. Budget redistribution is unnecessary for whole blocks.
- If the containing source range exceeds the budget, the builder uses the Stage 09 symmetric before/after calculation inside that range and redistributes unused space at its edges. If the selection alone exceeds the budget, its complete text remains the context body. Exact `[...]\n` and `\n[...]` markers identify every omitted document edge. The budget applies to source characters; marker text is additional, matching read-only context behavior.
- `src/selection-editor.ts` uses `Selected text` plus one `Context` field for smart requests. With smart context disabled it retains the original `Context before` and `Context after` fields and the unchanged `getSelectionContext()` implementation. `applyPreparedSelectionEdit()` and the native editor adapter were not changed.
- `smartSelectionContext` defaults to `true` in `src/settings.ts` and `src/types.ts`; missing or malformed persisted values normalize to `true`, while explicit `false` survives. `src/main.ts` forwards the setting only to selection coordination. The settings tab provides the **Smart selection context** toggle.
- `README.md` and `AGENTS.md` describe the default expansion, opt-out, source-character budget, structural-block handling, unchanged write target, and privacy implications. No dependency or provider/write-path change was added.
