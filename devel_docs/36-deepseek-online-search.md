# Stage 36: DeepSeek online search

## Status and scope

DeepSeek online search is implemented for Ask, Discuss, and Brainstorm with `deepseek-flash` and `deepseek-v4-pro`. The composer Web control defaults to **Off** and offers **Review** and **Auto**. Edit, quick actions, Modify Selection, Kimi/custom providers, and unsupported DeepSeek models do not gain Web retrieval; unsupported combinations fail clearly without an ordinary unsearched fallback.

All provider evidence in this record is loopback-only. No real-provider or paid verification was performed.

## Retrieval and extraction architecture

The main model receives only `web_search` and `web_fetch` declarations and directs sequential calls across multiple rounds. Every call includes a required, nonempty extraction goal of 1–1000 Unicode code points. **Review** displays and permits editing each executable query/URL and goal before that batch runs while preserving call IDs and tool names; **Auto** performs the same validation without the pause. Retrieval, extractor, verifier, and refine requests begin only after submission and, in Review, consent.

Every readable Search/Fetch result invokes exactly one AI extraction and verification loop using the same configured provider/model and streaming transport. Canonical retrieved title, snippet, summary, and content remain temporarily available to the extractor's local tools without a raw-size truncation limit. The extractor produces compact, question-focused claims, each backed by one to four exact verbatim quotes; it does not generate unsupported facts, summaries, paraphrases, or link labels. A same-provider verifier then marks each claim supported or unsupported using only the question, goal, and supplied claims with their quotes. Rejected claims receive up to two refine rounds, and claims that still lack support are dropped in favor of deduplicated quotes-only evidence or `no_relevant_evidence`. The main answering model never receives raw retrieved content or unverified AI-generated facts; it receives only a closed payload containing actual source IDs, titles, URLs, and either verified claims with their quotes or quotes-only evidence. Only successfully represented actual HTTP(S) results become stable citations.

The extractor receives the current typed question, reviewed extraction goal and target, and a source catalog. It has empty chat history and receives no active-note snapshot/path, earlier chat, instructions/skills, additional notes, or vault content. Its only tools are local, case-insensitive literal grep and UTF-16 ranged read over temporary canonical sources. Limits are 6 extractor model rounds, 4 local calls per round, 16 local calls total, and 4,000 characters per local tool result; at the round limit one forced no-tools request asks for the JSON answer. It has no network, vault, or note-writing tool. The verifier has empty history, no tools, no continuation from the extractor, and receives only the question, goal, and numbered claims with quotes; it receives no target, note, chat, instruction, additional-note, or vault context. Claims are capped at 8 per source and 24 total before verification, and the verifier request is capped at 24,000 serialized claim characters; claims outside that budget are neither verified nor refined and fall back to their result-level quotes. Refine requests also receive the reviewed target and bounded verifier reasons, with no tools or history. Claims, quotes, and verifier reasons are framed as untrusted external data that must never be followed as instructions.

Extractor terminal output is parsed tolerantly: fenced or prose-wrapped JSON is accepted, unknown fields are ignored, invalid individual claims/quotes are dropped, and unknown or duplicate source IDs are ignored or merged. Claims carry trimmed 1–500-code-point text and 1–4 exact verbatim quotes of 1–1,500 code points each; result-level deduplicated quotes are the fallback. One same-provider format-correction round handles structurally unparseable terminal output, and a second unparseable reply fails the extraction. A verifier pass is capped at three (initial plus one after each refine), missing verdicts mean unsupported, and unknown indices/sources are ignored. Verifier parse or provider failure stops the loop and returns verified claims so far, or the extractor's quotes-only outcome when none were verified; it never becomes `extraction_failed`. Oversized payloads are fitted deterministically by dropping trailing claims, then trailing evidence, then prefix-truncating the last quote with `truncated`, then dropping empty results or emitting `no_relevant_evidence`; raw retrieval is never passed to the main model. The main model synthesizes only from supplied claims, quoted evidence, and actual source metadata, and final-answer claims must remain supported by that evidence. Extractor, correction, verifier, and refine reasoning and artifacts are transient and are not appended to main-answer reasoning.

## Budgets, privacy, and cost

- `maxWebToolCalls` defaults to 8 and normalizes to 1–20 executed Search/Fetch calls. Every proposal is validated. An over-limit batch executes only the first remaining calls in model order; Review displays only those executable calls and uses their edited arguments. Continuations preserve every proposed call ID, reviewed executable arguments, original skipped arguments, ordinary selected outcomes, and small `call_limit_reached` outcomes for skipped calls. Skipped calls perform no Search/Fetch/reader work and gain skipped activities.
- After any skipped calls, Emend forces exactly one terminal main-model request without Web tools, using current note/chat and successful evidence. It may answer without evidence but must not invent citations; further tool calls fail without retrieval. Chat appends exactly one singular/plural skipped-call incompleteness warning and persists it as ordinary ready content. Exact-limit completion has no skipped-call warning.
- `maxWebContentCharactersPerCall` defaults to 20,000 and normalizes to 1,000–100,000. It applies independently to each complete serialized Search/Fetch extraction payload. For cap `C` and `N` executed calls, tool payloads contribute at most `C × N` characters; there is no independent total retrieval cap.
- `measureWebContent` currently reports UTF-16 character length behind a token-ready measurement interface. Emend does not claim exact tokenization, and `ceil(characters / 4)` remains only a usage fallback estimate.
- Main Web rounds receive ordinary captured note context, recent ready history, additional notes, and instructions/skills. Search/Fetch endpoints receive only the validated query or URL. Extractor requests receive only the isolated question/goal/target/catalog and bounded local tool continuations; verifier and refine requests receive only the question, goal, and claims with quotes.
- Review and Auto disclose that model arguments may contain note-derived text, the current question is sent to the extractor for every call, extractor/verifier/refine model rounds may incur separate charges, and sanitized activity metadata is stored locally. Changing controls, opening notes, and loading threads perform no request.

## Failures, usage, and persistence

Expected Fetch failures, including empty pages and target-site extraction/policy failures, return explicit unread outcomes without invoking an extractor. Their deterministic unread-page warning remains distinct from extraction failures. Search failures and Fetch HTTP 400/401/402/413 remain fatal. Every abort cancels the entire submission.

A non-abort extractor provider/format/limit failure produces only `extraction_failed`, excludes that query's unextracted sources, and permits the main model to use other successful evidence. Chat appends exactly one aggregate warning: `Emend could not extract information from N web query. The answer may be incomplete.` for one, or the corresponding `N web queries` plural. The warning persists as ordinary ready content. Verifier failure does not become `extraction_failed`; it falls back to verified claims or exact quotes. There is no automatic transport retry and no raw-content fallback. Usage covers every main, extractor, correction, verifier, and refine model round. Provider-sourced totals require a complete valid usage triplet from every round; otherwise all rounds are independently estimated and labelled **Estimated**. Search, retrieval, and reader prices or token counts are not invented.

Conversation schema 2 continues to persist only ready Review/Auto badges, sanitized result-backed citations, folded query/URL/outcome activity, main-answer reasoning, and usage. Raw retrieval, request bodies/tool arguments/results, extraction payloads, evidence extracts, extractor/verifier/refine reasoning and rounds, transient extraction state, and loading/error/stopped states are not persisted. Web retrieval has no note writer.

## Implementation boundaries

`provider-stream.ts` owns streamed function-call parsing, continuation messages, and optional JSON-mode bodies. `web-search.ts` owns shared Web types, closed Search/Fetch/extraction-goal validation, disclosures, and provider/model support. `web-search-modal.ts` owns editable batch review. `web-extraction.ts` owns canonical documents, bounded local tools, tolerant claim/quote parsing, deterministic cap fitting, and serialized-cap checks. `web-content-measurement.ts` isolates character measurement. `web-extraction-reader.ts` owns the bounded extractor loop, one format correction, and the verifier/refine loop. `deepseek-web.ts` owns retrieval, sequential main-loop integration, staged source registration, and failure outcomes. Read-only coordination supplies the isolated current question and configured cap and aggregates all-round usage without gaining a writer.
