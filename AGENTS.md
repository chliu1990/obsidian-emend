# Emend

## Project overview

This repository contains an Obsidian community plugin written in TypeScript and bundled with esbuild. The plugin provides context-aware, streamed AI chat for Markdown notes in explicit modes, guarded full-note editing in Edit mode, and guarded selected-text replacement. Closed JSON operations are the only model-facing edit protocol; valid operations compile into the same internal CriticMarkup and Track Changes path.

The repository contains the completed Emend rewrite:

- The **current implementation and release identity are Emend**. `manifest.json` uses plugin ID `emend` and name `Emend`; `package.json`, `manifest.json`, `package-lock.json`, and `versions.json` carry consistent release metadata. This is a clean plugin ID with no Lapis Lazuli data migration.
- Ask, Discuss, and Brainstorm modes, instruction/skill loading, and streamed chat are wired into the current runtime. These paths have no note writer. DeepSeek `deepseek-flash` and `deepseek-v4-pro` additionally support default-off Review/Auto web research through a bounded model-directed search/fetch loop; Kimi/custom providers and other DeepSeek models do not.
- Edit mode sends the complete captured note and privately buffers the response. The Operations-only strategy atomically validates/compiles closed JSON operations, then Stage 07 revalidates the resulting markup before stale source/target guards and one `vault.modify` write. Track Changes is the only review surface.
- The composer **Edit target** control defaults to Selection for usable selected text and Full note otherwise, with an explicit Full note override. Typed Edit and all three quick actions reuse the displayed target and one submission path; Selection failures cannot fall back to the full-note writer. Composer Selection captures exact offsets, sends the complete selection with default smart structural context or an exact Stage 09 symmetric opt-out and empty provider history, validates only the compiled annotated selection, and replaces only the captured range through `editor.replaceRange` for native undo. Ready chat keeps concise results, all-round usage, and successful-attempt reasoning. The separate Modify Selection command captures exact offsets before opening its unchanged instruction modal, uses the same selection coordinator and native writer, and retains its existing notices without chat, usage, or retry-status displays. Operation targets cannot address text outside that selection.
- The dormant diff module, editor extension, callbacks, styles, and CodeMirror dependencies are removed.

The manifest requires Obsidian `1.11.4` or newer and sets `isDesktopOnly` to `true`. The streaming provider transport uses desktop browser `fetch` and Server-Sent Events; mobile support is not currently declared.

## Technology stack and build process

- TypeScript with strict compiler checks; source files are under `src/`.
- Obsidian API for plugin lifecycle, workspace views, Markdown rendering, settings, vault access, and notices; browser `fetch` and Server-Sent Events for provider streaming.
- esbuild bundles `src/main.ts` into a CommonJS `main.js` at the repository root, targeting ES2021.
- Obsidian, Electron, CodeMirror/Lezer modules, and Node built-ins are external to the bundle and supplied by the host. Other runtime code must be bundled; do not add unbundled runtime dependencies.
- Development builds include inline source maps and are unminified. Production builds are minified and have no source map.

### Commands

Use npm from the repository root:

```bash
npm install
npm run dev
npm run build
npm run lint
npm test
```

- `npm install` installs the dependencies in `package.json`. Use `npm ci` with the committed `package-lock.json` for reproducible installs and CI.
- `npm run dev` starts esbuild in watch mode and writes `main.js`. It does **not** run TypeScript type checking; use the production build or `npx tsc -noEmit -skipLibCheck` for that check.
- `npm run build` runs `tsc -noEmit -skipLibCheck` and then creates the production `main.js`.
- `npm run lint` runs ESLint over the project using the typed `typescript-eslint` setup and `eslint-plugin-obsidianmd` recommended rules.
- `npm test` runs Vitest once; `npm run test:watch` starts watch mode. Tests use the `obsidian` mock alias and must not access a real vault or the network.

`main.js`, source maps, `node_modules/`, `test_vault/`, and Obsidian's local `data.json` are gitignored. Do not commit generated bundles, vault content, mock credentials, or local plugin settings.

## Current runtime architecture

### Target note and request context

`main.ts` targets the active Markdown view when available. If focus is in the chat sidebar, it uses the last active still-open Markdown view, then falls back to another open Markdown view. `captureChatContext()` synchronously captures the target `TFile`, full source text, selection offsets, note label, optional vault-qualified path, and bounded Markdown before instruction reads or networking.

Read-only requests include bounded Markdown context. Notes within the configured character limit are sent whole; longer notes are windowed around the selection or caret, with `[...]` markers at omitted edges and unused budget redistributed toward available text. The default limit is 12,000 characters and the settings UI enforces a minimum of 1,000. Full-note Edit ignores the bounded `markdown` window and always sends `sourceText`. Modify Selection always sends the complete selection. Smart selection context defaults on and expands to containing paragraph(s), complete document-leading YAML, and complete fenced code before adding whole adjacent blocks within the source-character budget; oversized containing blocks use symmetric marked truncation without changing the target. Disabling it restores Stage 09 symmetric before/after context, including empty surroundings for an oversized selection. Vault name and note path are opt-in and disabled by default.

Additional notes are chosen only through the explicit **Add notes** Markdown picker. The in-memory store keeps ordered paths per target note, deduplicates the active note and repeats, shares selections between chat and Modify Selection for that target, and never shares them across different targets. Selections survive target-note switches during the current plugin session, clear on plugin or Obsidian reload, and are never persisted. Vault rename events update selected/target paths; open pickers and Modify Selection resolve the captured target `TFile`'s live path, and controls close their owned picker on destroy. Delete events remove deleted included paths. A missing-path race rejects the entire capture before any selected-note read, instruction read, or provider request. Opening the picker lists vault Markdown paths; selecting/opening/switching notes performs no content read or provider request.

At submission, coordinators capture the selected path array before their first await and resolve/read fresh selected-note content. Additional notes use a separate combined `maxContextCharacters` source budget: each note receives `floor(remaining budget / remaining notes)`, included source characters are subtracted, and unused capacity rolls forward. Capture begins at source offset zero because no additional-note caret/selection exists; omitted suffixes end with an exact `[...]` marker. Labels, prompt fences, and markers are additional to source-character accounting. Each snapshot's outer prompt fence is longer than its longest backtick run. Each separately numbered prompt section says the notes are read-only and not edit targets. With path sharing off, no source/basename/vault path label or metadata is added to the additional-note prompt; with it on, a `Path: <vault>/<note path>` line is included. Note content itself is preserved within the captured budget. Frontmatter, wikilinks, fenced code, math, Unicode, and empty files pass through unchanged within the captured budget. These snapshots never become write targets in any mode.

### Sequential edits and per-note request isolation

`main.ts` owns one pending-path registry shared by every chat mode and Modify Selection. After synchronous target capture and nonempty prompt validation, `withNoteRequest()` acquires the captured note path before instruction reads or networking. A second request for that path rejects with exactly `Wait for the current Emend request to finish.`; different note paths can proceed independently. The single chat view also disables its own duplicate UI submissions while sending.

The submission captures mode and source before awaiting. Each sequential Edit therefore uses the latest complete annotated note as its source, preserves earlier Track Changes tokens, and sends only ready user prompts plus concise applied-edit summaries as assistant history. Full annotated responses remain private and are never persisted.

The pending path is deleted in `finally` only after the coordinator settles on success, provider error, validation error, stale failure, or abort. Stop, chat close/note-switch aborts, and selection cancel/close therefore permit a retry without weakening the existing post-await abort, exact-source, active-target, or permission checks. A pending old-note request remains keyed to its captured path and cannot apply to a newly active note.

### Streamed chat and guarded editing

1. `chat-view.ts` initializes one mode from `defaultMode` and a default-off Web mode per view session. Switching notes resets neither the mode nor Web selection. Ask, Edit, Discuss, and Brainstorm use their Stage 03 icons, badges, and placeholders. Enter and Mod+Enter submit through the normal path, with Mod+Enter registered on the view's Obsidian `Scope` and restricted to the live composer so the window keymap cannot swallow it. Shift+Enter remains a newline, and disabled/loading controls reject shortcut submission. The `emend:switch-to-ask-mode` and `emend:switch-to-edit-mode` commands use default Mod+Shift+A/E hotkeys, open/focus chat, preserve the composer draft, and only change the next-request mode; they never submit, request, write, or abort a pending submission.
2. The two-value **Edit target** selector remains visible in every mode because quick actions enter Edit. Automatic targeting resolves Selection only when `hasUsableSelection()` finds non-whitespace selected text in the maintained target view and Full note otherwise. An actual target-note change resets the choice to automatic; an explicit Full note or Selection choice otherwise survives same-note renders and mode switches. Submission follows the maintained displayed target and synchronously captures ordinary context or, only when Edit displays Selection, the exact `{ snapshot, editor }`, then captures that source's current additional-note path array, the current read-only Web mode, and up to the last eight ready chat messages before the first deferred save. Displayed Selection capture fails closed with the existing Notice and no messages, saves, provider call, or full-note fallback; only after that failed capture, a draft-preserving render synchronizes the visible mode and Web controls with the preserved quick-action Edit intent. The Edit placeholder neutrally covers the note or selection. Read-only modes never route to a selection writer. Duplicate submissions are disabled while a request or thread load is active, and additional-note add/remove/clear controls are disabled while loading or sending. The Fix grammar, Make concise, and Add examples buttons above the composer select Edit, force Web off, and call this same submission path exactly once with their mapped prompts; they are disabled without a note thread and during loading or sending. They have no separate provider, history, persistence, pending, or writer path.
3. `ReadOnlyRequestCoordinator` resolves/captures required additional notes before loading current vault instructions on every request and builds the selected read-only prompt with skills before agent instructions and separately labeled additional-note sections after active-note Markdown. It calls ordinary `requestAiResponse` with Web off or routes supported opted-in submissions through `DeepSeekWebSearchCoordinator`. Its dependencies and submission contract contain no note writer. Completed results resolve valid provider usage or a clearly sourced estimate from the exact request/response rounds.
4. Full-note Edit uses `EditRequestCoordinator` with the guarded vault writer. Displayed Selection Edit instead calls `requestSelectionEdit()` with the exact synchronous capture, empty provider history, the shared reasoning/retry callbacks, and the guarded native editor writer. `EditRequestCoordinator` captures additional notes before instructions, uses the Operations-only full-note prompt, forwards reasoning while privately buffering content until provider completion, and rejects aborts. Operations require a bare closed-union JSON array, exact original active-note anchors/targets, occurrence disambiguation, and nonoverlapping/unambiguous ranges before structural classification and compiling. Typed actionable validation diagnostics identify bounded operation/match details. Additional-note-only anchors fail without a write. Valid replacements compile to deterministic Unicode word/segment-level multi-hunk CriticMarkup, with response-scoped work bounds, whole-target fallback for backtick-containing replacements, and single-substitution fallback for expensive replacements rather than character-minimal fragmentation. A candidate-validation failure triggers exactly one automatic correction request to the same provider: the unchanged original request plus the invalid response and bounded diagnostic feedback, with no delay/backoff/setting and at most two calls. A second invalid response is terminal; provider, abort, stale, and write failures never start another correction. Stage 07 `prepareCriticMarkupEdit` revalidates the compiled markup before `applyPreparedEdit`. Composer full-note and Selection usage covers every attempted round; only successful-attempt reasoning survives a retry in the ready message. Raw candidates, operations, and correction feedback stay out of ready chats and persistence. `getEditStrategy()` takes no settings and always returns this operation strategy.
5. `applyPreparedEdit` returns without reading or writing for read-only modes and unchanged responses. For a changed Edit response it re-reads the captured file, immediately rechecks the request abort signal, requires both exact source equality and the same active target, checks `canWriteToNote(mode)` immediately before writing, and calls `vault.modify` exactly once. The stale error is `The note changed while Emend was responding. No edits were applied.`
6. Read-only loading content appears immediately as plain text, without queuing asynchronous Markdown renders. Ready and stopped content renders through Obsidian `MarkdownRenderer` with the captured file path as source path, guarded against closed views and disconnected elements. Reasoning is plain text in a closed `details` element. Ready Web activity renders as a folded query/URL/outcome list and retrieved sources as folded safe external links with optional plain-text snippets; copy appends the Markdown source list. Model output and retrieved content are never assigned with `innerHTML`. The chat preserves the reader's position when not following latest. New submissions and streaming follow the bottom, successful completion aligns the completed response's header and beginning to the top after current Markdown layouts settle, and unrelated re-renders preserve upward readers.
7. Edit responses are never rendered into chat. Success stores only `Edit applied — N changes tracked. Review in Track Changes.` as assistant history; unchanged responses store `No changes were needed.` Valid comment-only edits may apply with zero text changes. Ready assistant footers show total/prompt/completion usage and its provider/estimated source, including Edit summaries and all Web model rounds; loading, stopped, error, and user messages have no usage footer.
8. Stop aborts the active request and closes any Web review modal. Success, provider/retrieval errors, validation errors, stale errors, and aborts all clear loading state. Stopped partial responses and errors are excluded from later ready-message history and local persistence.

### Structural Markdown edit safeguards

1. Backtick-containing replacements use whole-target CriticMarkup so code delimiters remain reviewable. Remove/replace/comment targets intersecting inline code must contain the complete span, and insertions must be outside it without extending delimiter runs; content-only/cross-delimiter targets fail with `inline-code-range` and the normal one-correction opportunity. Complete spans and larger targets containing complete spans remain valid. Matching stops at blank-line and actual block boundaries while preserving valid lazy multiline spans, inline HTML, and autolinks.
2. Any target intersecting fenced code, including comments and larger containing targets, fails with `fenced-code-edit`. Semantic guards cover containers and unclosed blocks. Separate Track Changes 2.3.0 compatibility ranges recognize only zero-to-three-space bare openers and exact closing runs, continuing through blank lines, prefixes, and different-length runs until the exact later bare delimiter or EOF. List-created shadows and longer top-level closers therefore reject, while top-level/blockquote following prose remains reviewable. Nested semantic openings inside other review shadows reject. Every `closingContentEnd` insertion before the original line ending rejects; insertion after the closing line ending remains safe.
3. `markdown-edit-guards.ts` handles CRLF, escaped delimiters, outer table whitespace, backtick/tilde fences, container structure/indentation, and block-level table termination. Tables allow only text edits wholly within one existing header/body cell. One replacement-compilation pass supplies actual `compiledText`; all Operations per original row compose at actual compiled offsets, with zero-width insertions at `insertionPoint`, before comparing original/actual annotated/accepted/rejected delimiter, outer-pipe, cell-count, and block identity. This covers minimized fragmentation, composed backslash parity, actual insertion offsets, and four-space/tab indented-code exits. Delimiter, row/column, spanning, CR/LF, unescaped-pipe, and true HTML/fence block-start changes fail with `table-structure-edit`; escaped pipes, ordinary text, inline HTML/autolinks, and invalid backtick-fence info remain safe. Occurrence resolution and existing range-isolation checks run first, followed by one replacement-compilation pass and composed structural validation using actual `compiledText`. One violation rejects the entire candidate before final CriticMarkup validation or either writer runs. These are targeted conservative scanners, not full CommonMark coverage.
4. Selection passes full-note text and absolute offsets through `prepareEditResponse` solely for structural classification. Occurrence resolution, permissions, compilation, and replacement still use only captured `selectedText`; structural context never expands the target.
5. Raw markup displayed while the cursor is inside a table cell is upstream Obsidian/Track Changes presentation, not claimed fixed; accept/reject byte correctness is the criterion. Comments before/after replacements showed no ordering bug and retain their existing semantics. Stage 38 records the 35-file/817-test gate and 66-scenario fixed-v4 real-Obsidian evidence with two environment-limited CRLF setups.

### DeepSeek online search

1. The composer **Web** selector offers **Off**, **Review**, and **Auto** only for read-only submissions; it defaults to **Off** per view and is disabled in Edit and while loading/sending. Changing it performs no request. Review/Auto are supported only for DeepSeek `deepseek-flash` and `deepseek-v4-pro`. Kimi/custom providers and other models fail with `Online search is only available for DeepSeek deepseek-flash and deepseek-v4-pro.`; they never silently become ordinary unsearched chat.
2. Enabled main-model requests add only `web_search` and `web_fetch` declarations with `tool_choice: 'auto'`. Each call requires a nonempty `extractionGoal` of 1–1000 Unicode code points alongside its query or URL. The model decides whether retrieval is useful, may request multiple calls and rounds, and may legitimately choose zero calls. Emend validates every proposal's closed arguments, executes accepted calls sequentially, and emits content only from the terminal no-tool round while forwarding main-model reasoning across rounds. The main-model chat transport has no retry; Search and Fetch each allow the single bounded immediate retry described in item 6. There is no raw fallback or alternative provider.
3. **Review** opens an editable query/URL/extraction-goal modal before every executable batch, revalidates edits, and preserves call IDs/tool names; closing or cancelling aborts. **Auto** skips only that review pause. The disclosure states that DeepSeek may derive arguments from note context, successful retrieval may be billed separately, every call uses an AI extractor that receives the current question and extraction goal for up to 6 extractor rounds plus a verifier and up to 2 refine rounds with possible separate charges, a transient Search or Fetch failure may be retried once, failed calls still count toward the configured call limit, and query/URL/outcome metadata is stored locally. Main model rounds contain ordinary context/history/additional notes/instructions, while retrieval endpoints receive only the validated query or URL.
4. `maxWebToolCalls` defaults to 8, normalizes finite values to integers clamped to 1–20, and caps executed Search/Fetch calls. An over-limit batch executes only the first remaining calls in model order; Review shows only those executable calls and uses their edited arguments. Continuation preserves every proposed call ID, reviewed executable arguments, original skipped arguments, ordinary selected outcomes, and small `call_limit_reached` outcomes for skipped calls. Skipped calls perform no Search/Fetch/reader work and gain skipped activities. Emend then forces exactly one terminal main-model request without Web tools, answering from current note/chat and successful evidence; further tool calls fail without retrieval. Ready answers may have no evidence but cannot invent citations. Chat appends exactly one singular/plural skipped-call incompleteness warning when the skipped count is positive and persists it as ordinary content; exact-limit completion has no warning. `maxWebContentCharactersPerCall` independently defaults to 20,000 and normalizes to 1,000–100,000. It caps each complete serialized Search/Fetch extraction payload, so `N` executed calls contribute at most `C × N` characters with no separate total cap. `measureWebContent` currently measures UTF-16 `string.length` behind a token-ready character-unit interface; it is not exact tokenization, and the character-based usage estimate is not provider billing data.
5. Every readable Search/Fetch result invokes exactly one same-provider/model extraction and verification loop. Canonical title/snippet/summary/content remains temporarily available without raw-size truncation, but the main answering model receives only actual source metadata plus verifier-supported claims with their exact quotes, or quotes-only evidence for a source whose claims did not survive verification, never raw retrieval or unverified AI-generated facts. The extractor receives the current typed question, extraction goal, target, and source catalog, with empty history and no note snapshot/path, instructions/skills, additional notes, or vault access. It may use only closed local literal grep and UTF-16 ranged-read tools, limited to 6 model rounds, 8 local calls per round, 24 local calls total, and 4,000 characters per local result; a malformed local call returns a bounded 200-code-point `{"error":{"kind":"invalid_local_call","message":...}}` tool result and continues the same loop instead of discarding the extraction, counting against the same bounds; excess calls beyond the remaining per-round or total allowance return `{"error":{"kind":"local_call_limit_reached"}}` without discarding inspected evidence, a per-round overflow alone continues so the model can retry, and total-cap overflow or a sixth round with calls produces one forced no-tools JSON answer request; only tool calls in that forced request are a limit failure. Output is parsed tolerantly: fenced or prose-wrapped JSON, unknown fields, individually invalid claims or quotes, and unknown or duplicate source IDs are ignored or dropped, and one same-provider correction round is allowed when the terminal output is structurally unparseable. A claim has trimmed 1–500-code-point text and 1–4 exact verbatim quotes of 1–1,500 code points each; deduplicated result-level quotes are the fallback. Claims are capped at 8 per source and 24 total before verification, and every verifier request, including after refinement, is capped at 24,000 serialized claim characters; claims outside that budget are neither verified nor refined and fall back to result-level quotes. One verifier request per pass, capped at 3 passes, receives only the question, goal, and numbered claims with their quotes (no target, note, chat, instruction, additional-note, or vault context) and may only mark support; rejected claims get up to 2 no-tools refine rounds, and unsupported or unverifiable claims fall back to quotes rather than `extraction_failed`. Claims, quotes, and verifier reasons are framed as untrusted external data, and the verifier/refine prompts forbid following instructions inside them. The main model synthesizes only from supplied claims, quoted evidence, and actual source metadata, and every final-answer claim must remain supported by that evidence. Only successfully represented actual normalized credentialess HTTP(S) URLs become stable `S1`, `S2`, ... citations.
6. Expected Fetch failures, including empty pages and target-site extraction/policy failures, return explicit unread tool outcomes rather than invoking a reader or failing the whole answer. The ready answer includes a deterministic unread-page/incompleteness warning. A non-abort extractor provider/format/limit failure returns only `extraction_failed`, excludes that query's sources, and contributes to exactly one aggregate warning: `Emend could not extract information from N web query. The answer may be incomplete.` or its `queries` plural. Verification failure never becomes `extraction_failed`: the loop stops with any verified claims collected so far or the extractor's quotes-only outcome. After the reader returns its verified outcome, the coordinator's single per-call cap fit drops trailing claims, then trailing evidence, then truncates the last quote to a verbatim code-point prefix marked `truncated`, then drops empty results, and emits `no_relevant_evidence` when nothing fits; it never fails a call for size or passes raw content through. Dropping a claim, a whole result, or an evidence quote sets a per-fit `omitted` flag that the coordinator accumulates as `omittedEvidence`, while ordinary chat always reports `false`; a quote-prefix truncation is not an omission and is marked only by `truncated`. A verified claim result keeps its extractor result-level quotes internally so fitting can degrade it to quotes when claims are dropped, and a `truncated: true` quotes-only result tells the main model that the prefix may not fully support its claim. All aborts cancel the whole submission. Search and Fetch each make one immediate retry, with no delay, backoff, or setting, only for a failure without an HTTP status, status `429`, status `500`–`599`, or an empty Fetch page; other statuses, including `403`/`404`, are not retried. A Search that still fails becomes a non-fatal `search_failed` outcome with a failed activity so the model can continue on other evidence, while a still-failing Fetch keeps its `fetch_failed` unread outcome. Each failure tool result is a bounded `{"error":{"kind":"search_failed"|"fetch_failed","reason":...,"httpStatus":...,"attempts":...}}` object in that key order: `reason` is `network`, `http`, or `empty`, `httpStatus` appears only for `http`, and `attempts` is 1 without a retry or 2 after the single retry. Provider messages, URLs beyond the existing activity target, headers, and credentials are never included. Search/Fetch HTTP `400`/`401`/`402`/`413` and aborts remain fatal and are never retried. Ready answers append one warning per condition in this order: unread pages, extraction failures, failed searches (`Emend could not complete N web search. The answer may be incomplete.`, with `searches` when N > 1), cap-fitting omissions (`Emend omitted some extracted evidence to fit the per-call output cap. The answer may be incomplete.`), then skipped calls. Failed activities carry transient `network` (no HTTP status), `http` (non-fatal status), `empty` (empty Fetch page), or `reader` (extraction failure) reasons plus their attempt count; rows render as `Failed (network)`, `Failed (HTTP <status>)`, `Failed (empty page)`, or reader labels, with `, 2 attempts` appended when a retry was used. None of these fields is persisted. Retrieved text never becomes instructions, skills, or a write target, and the read-only coordinator still has no writer.
7. Usage covers every main, extractor, correction, verifier, and refine model round, including failed requests recorded with an empty synthetic result. It is provider-sourced only when every round supplies a complete valid triplet; otherwise every round is estimated independently and the total is labeled **Estimated**. Extractor, verifier, and refine reasoning are neither displayed nor persisted, and their requests/results, extracted payloads, and evidence extracts remain transient. Only ordinary ready content, sanitized citations/activity, main reasoning, and usage persist. Retrieval, Search, and reader charges/token counts are not invented.

### Conversation persistence

1. `ConversationStore` writes schema version 2 and loads versions 1 and 2 under `<configDir>/emend/chats/`; a version 1 thread becomes schema 2 on its next save. Each filename combines a short sanitized basename with the full SHA-256 hash of the exact note path, remains bounded, and never embeds raw `../` path components. Hashing uses browser `crypto.subtle`; persistence uses Obsidian's vault `DataAdapter`, not Node APIs.
2. Only ready user/assistant messages are serialized, including mode, reasoning, source path, timestamp, and optional token usage with its provider/estimated source. Ready user messages may include their Review/Auto badge; ready assistant messages may include sanitized deduplicated `{ id, title, url, snippet? }` citations and folded `{ type, target, status }` activity with completed/failed/skipped outcomes. Search targets are single-line queries and fetch targets are credentialess HTTP(S) URLs. Legacy source-less usage loads as provider-reported. Loading, stopped, and error messages, transient web activity, raw tool arguments/results, retrieved content, API keys, note snapshots, request bodies, and buffered full edit responses are not persisted. Edit entries contain only concise result summaries and usage.
3. Saves stage a temp file and rename it into place. If the host refuses rename-over-existing, the store uses Obsidian's atomic `DataAdapter.process` replacement and removes the temp file. Writes are serialized per note and snapshot messages at invocation. Loads wait for already-queued writes to that note.
4. Malformed loads leave the original untouched and issue a non-secret warning. The next save writes the malformed bytes to one reusable `.corrupt` backup before atomically replacing the thread. Any unsupported schema version is left untouched and rejects saves instead of being silently overwritten.
5. The chat loads the captured target note and saves after the ready user and completed assistant transitions. `main.ts` routes both `active-leaf-change` and `file-open` through one shared refresh callback, covering same-leaf file navigation without separate racing flows. Generation checks prevent stale async loads from replacing a newly selected note's messages, and repeated same-note events return without a new load. Switching notes aborts the active request and does not reset the per-view mode. Deleting a note does not delete its thread.

### Guarded selection editing

1. The `emend:modify-selected-text` editor command is available only for a nonempty Markdown selection. It synchronously captures `SelectionSnapshot { file, fullText, selectedText, from, to }` and the source-view adapter before opening the instruction modal. The serializable snapshot contains no editor or view.
2. Opening the modal makes no request. It renders the same target note's shared additional-note controls; submission captures that path array before its first await. An explicit nonempty instruction or one of the shared Fix grammar, Make concise, and Add examples actions captures additional notes before current instructions/skills, uses the Operations-only selection prompt and Stage 05 streaming transport with no chat history, and privately buffers the response rather than rendering it as a chat answer. Every action calls the same `submit(prompt)` path exactly once, requires no typed input, disables the input, quick actions, and additional-note controls while pending, and re-enables them on settlement when the modal remains open.
3. `buildSmartSelectionContext()` returns exact unchanged `from`/`to` and complete `selectedText` plus smart `contextText`. It includes containing blocks first, then whole adjacent blocks before-side first and after-side second while they fit. Exact `[...]` markers decorate omitted edges and are additional to the source-character budget. The opt-out uses the unchanged Stage 09 before/after builder and prompt fields. Neither path expands the edit target.
4. Operations compile against exactly the captured selection with the same bounded word-aware replacement minimization and typed diagnostics as full-note Edit, then Stage 07 revalidates the compiled CriticMarkup selection. A candidate-validation failure makes exactly one same-provider correction request with the invalid response and bounded feedback; the second invalid response is terminal. Anchors and targets outside that selection fail before any read or replacement. The response is merged into captured full text for no-op handling; unchanged responses do not read or replace. Selection returns token usage alongside its applied/changeCount result and supports optional reasoning/retry callbacks. Composer Selection passes those callbacks and persists concise ready results with all-round usage and successful-attempt reasoning; the existing modal does not pass the callbacks and still has no chat, token-usage, or retry-status displays.
5. Before replacement, the current editor value must equal captured full text, the captured view must still reference the captured file and be the current target, and the signal and `canWriteToNote('edit')` checks must pass. One `editor.replaceRange` at captured offsets performs the only write, preserving native Obsidian undo. Selection edits never call `vault.modify`; stale source/target uses the same stale error as full-note editing.
6. Cancel/Stop and modal close abort pending requests. Provider, validation, abort, and stale failures replace nothing and release the pending controls for retry. Track Changes remains the only review UI.

The legacy JSON answer/edit protocol, accumulating adapters, inline suggestion command/extension/module, inline styles, dormant diff UI, and in-plugin Apply/Reject flow are removed. Track Changes provides the only CriticMarkup review UI.

### Providers and settings

DeepSeek, Kimi, and custom providers all use one OpenAI-compatible streaming chat-completion transport in `provider-stream.ts`. The editable presets are DeepSeek model `deepseek-flash` at `https://api.deepseek.com` and Kimi model `k3.1-pro` at `https://api.kimi.com/coding/v1`. Each provider has an editable HTTP(S) base URL, API key, model, reasoning-effort setting, and `requestUsage` compatibility toggle. The toggle defaults on for DeepSeek/Kimi and off for custom. Requests use browser `fetch` with `stream: true`, `temperature: 0.3`, the configured `reasoning_effort`, and at most the last eight history messages. Base URLs are trimmed of trailing slashes before `/chat/completions` is appended. `stream_options: { include_usage: true }` is present only when `requestUsage` is true; provider rejection remains an error with no chat-transport retry, so users can disable the option. Reader extractor, correction, verifier, and refine requests additionally send `response_format: { type: 'json_object' }`; main Web loop rounds and ordinary chat requests do not. Content and reasoning deltas are emitted separately, with optional final token usage and a done event. Usage parsing requires a complete nonnegative integer triplet and preserves zero. Provider errors include HTTP status and available provider details without credentials. Web-enabled DeepSeek rounds additionally send the two tool declarations, `tool_choice: 'auto'`, and any tool continuation messages; ordinary requests are unchanged. Only DeepSeek web retrieval uses separate JSON `POST <base URL with one /v1>/tools/search` and `/tools/fetch` calls. There is no `requestUrl`, Gemini/Claude transport, fallback provider, or automatic retry on the chat transport for provider failures. The bounded retry exceptions are the single immediate web Search/Fetch retry in `deepseek-web.ts` (retryable only for a missing HTTP status, `429`, `500`–`599`, or an empty Fetch page), the explicit Edit/Modify Selection candidate-validation round documented above, and the reader's single format-correction round documented above; each uses the same provider, and no correction is triggered by provider or write failures.

When valid provider usage is absent, chat coordinators estimate request and response tokens independently as `max(1, ceil(characters / 4))`, using system prompt, retained history, current user prompt, tool declarations/continuation content, response content, and reasoning. Web usage is provider-sourced only when every round has a complete valid triplet; otherwise all rounds are estimated independently and summed. Estimated total is prompt plus completion and is always labeled `Estimated`; it is not provider billing data. Web search adds no pricing, tokenizer, or model-metadata network calls.

Settings are loaded with `loadData()` and normalized against defaults. On first load, any legacy plaintext provider key is written to its exact `app.secretStorage` ID (`emend-api-key-deepseek`, `emend-api-key-kimi`, or `emend-api-key-custom`), cleared in memory, and saved back sanitized. Requests resolve each active provider's key through `getApiKey()` with per-provider in-memory fallback; masked settings inputs use `getApiKey()`/`setApiKey()`. Every `saveSettings()` serializes a deep sanitized clone whose three provider `apiKey` fields are empty, regardless of caller mutations. Non-secret per-provider configuration including `requestUsage`, active provider, default mode, note-path inclusion, smart selection context, context size, `maxWebToolCalls`, and `maxWebContentCharactersPerCall` is stored locally in Obsidian plugin data. The Web call setting defaults to 8, clamps finite values to 1–20, and uses the default for malformed values. The independent Web output cap defaults to 20,000 characters, clamps finite values to integers from 1,000 through 100,000, and restores 20,000 for malformed values. There is no edit-strategy setting or selector; legacy `editStrategy` values are dropped during normalization because Operations is always used. `smartSelectionContext` defaults to `true`; missing or malformed values normalize to that default, while explicit `false` restores Stage 09 behavior. Ready chat threads use the separate versioned conversation store; stopped/error states are not persisted.

## Coding conventions

- Follow the existing TypeScript style: tabs for indentation, single quotes, semicolons, trailing commas where used, and `async`/`await` for asynchronous work.
- Keep strictness intact. `tsconfig.json` enables `strict`, `noImplicitReturns`, `noFallthroughCasesInSwitch`, `noUncheckedIndexedAccess`, `isolatedModules`, and consistent file-name casing. Handle possibly missing indexed values rather than suppressing these checks.
- Use Obsidian DOM helpers and `MarkdownRenderer`; keep user-facing copy short and in sentence case. Use the correct window's animation-frame APIs for popout compatibility and never inject model output with `innerHTML`.
- Register views, editor extensions, workspace events, commands, and other disposable resources through Obsidian's registration helpers so unload/reload cleans them up. Abort active chat and selection requests, close Web review, and cancel pending renders when their views close.
- Keep ordinary chat completions on the streaming `fetch` transport in `provider-stream.ts`. Do not reintroduce `requestUrl`, a second chat-completion stack, or silent retries. Provider-specific capabilities such as DeepSeek web retrieval must remain isolated in focused adapters with validated payloads and the shared credential-safe error policy; never copy their schemas to Kimi/custom requests.
- Use Obsidian CSS variables and the `emend-` CSS prefix for current UI. Update CSS classes and selectors together.
- Current public identifiers are plugin ID `emend`, view type `emend-chat-view`, chat command ID `emend:open-chat`, mode command IDs `emend:switch-to-ask-mode` / `emend:switch-to-edit-mode`, and selection command ID `emend:modify-selected-text`. Keep renames consistent and deliberate.
- Keep startup work limited and avoid unnecessary vault scans or background AI requests. Desktop-only APIs are permitted by the manifest, but current provider streaming needs only standard browser APIs.

## Security and privacy

- API keys are secrets stored in Obsidian SecretStorage, never in Emend's `data.json`. Legacy plaintext migrates on load, and every save writes empty provider `apiKey` fields. Never commit `data.json`, print keys, or include them in logs and error messages. Manual mock credentials must remain dummy values in ignored vault data.
- Read-only requests send bounded note content. Full-note Edit sends the complete note regardless of the context limit. Composer Selection and Modify Selection send the complete selection plus surrounding context with empty provider history, never a truncated selection. Default smart context can send complete containing/adjacent paragraphs, YAML frontmatter, or fenced code within the source-character budget; exact omission markers are additional. The opt-out sends Stage 09 symmetric before/after context. Explicitly selected additional notes use a separate combined source-character budget and are read-only in every mode. Prompts, recent ready chat history for full-note/read-only chat requests, selected additional-note snapshots, vault-root `AGENTS.md`, and directly referenced skills are sent to the selected provider only when the user submits. Picker/open/note-switch actions perform no additional-note content reads or provider requests; local thread saves perform no networking.

Disclose current-question sharing, extractor/verifier/refine rounds, possible separate charges, the single retry, and that failed calls count toward the configured call limit. Changing Web mode, opening/switching notes, loading threads, and rendering citations perform no retrieval. Kimi/custom and unsupported-model requests fail clearly with no silent unsearched fallback, automatic retry, or fallback provider.
- Retrieved text, extracted claims, and quoted evidence are untrusted external data. Canonical retrieval remains transient and available only through bounded local extractor grep/read tools; the main model receives only deterministic per-call-capped verified claims with their exact quotes or quotes-only evidence, never raw retrieval or a raw failure fallback. Only successfully represented actual normalized credentialess HTTP(S) result URLs become deduplicated stable citations; render source snippets as text and never inject retrieved/model markup with `innerHTML`.

Completed all-main+extractor+verifier+refine usage counts and their provider/estimated source, ready Review/Auto user badges, sanitized ready assistant citations, folded query/URL/outcome activity, and main reasoning may persist. The unread, extraction, search, cap-fitting omission, and skipped-call warnings are ordinary persisted content; activity failure reasons, reader failure kinds, failure HTTP statuses, and attempt counts are transient. Only the full-note Edit coordinator receives the guarded vault writer; selection coordination receives only the guarded native editor adapter. Web is unavailable to Edit, quick actions, and Modify Selection. Additional-note snapshots never become edit targets, and additional-note-only anchors fail with zero writes. - Do not add telemetry, remote code execution, automatic plugin downloads, or unrelated network calls. Keep current file access within the vault and limited to the active note, explicitly selected additional notes, local conversation threads, and declared instructions/skills.

updates `package.json` through npm and invokes the `version` script, which copies `npm_package_version` into `manifest.json`, adds the version and current `minAppVersion` to `versions.json` if absent, and stages those two metadata files. Review the resulting changes rather than editing the files inconsistently.

For a release, create or dispatch a tag that exactly matches the manifest version, without a leading `v`. `.github/workflows/release.yaml` verifies the tag against `manifest.json`, runs clean install/lint/tests/build, and publishes `main.js`, `manifest.json`, and `styles.css` as individual GitHub release assets. Keep `minAppVersion` and the `versions.json` mapping accurate when adopting newer Obsidian APIs.

GitHub Actions runs lint, tests, and the production build through `.github/workflows/ci.yaml` on `ubuntu-latest` with Node 24. The release workflow uses `softprops/action-gh-release` with repository-scoped `contents: write` permission; CI uses `contents: read`. Verify the relevant GitHub run before publishing or merging.
